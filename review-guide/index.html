Meta App Review Guide

Bomuhamu / BomBom Threads Manager

Last updated: 2026-10-13

What this page is: Testing and permission-use instructions for a personal Windows-based Threads community management app. This is a documentation website, not the app itself, and does not indicate that Meta has approved the requested permissions. Reviewer access, a screencast and the permission request must be supplied through Meta App Dashboard by the app administrator.

1. Sign-in and review setup

  1. Start the local BomBom Threads Manager application on Windows and open its Streamlit interface.
  2. Use the application's Threads authorization/re-authorization flow to show the Meta/Threads OAuth consent and the permissions being requested. Never expose an access token, client secret or private configuration in the video.
  3. Show the connected authorized Threads account and current permission status inside the app.
  4. For the review submission, provide a screen recording of these steps and any reviewer access instructions required by Meta App Dashboard. A public GitHub Pages URL is not a substitute for functional app access or a demonstration.

2. threads_keyword_search — user-initiated public content discovery

Why requested: The authenticated user searches public hamster-related discussions and reviews relevant posts for their own community account. Search terms are chosen or reviewed by the user, for example hamster, ハムスター, or 햄스터.

  1. Open Candidate Discovery and enter a hamster-related keyword.
  2. Run Search Now and display the returned public posts, their links and candidate scoring.
  3. Open a selected public post for user review, showing the connection between the search result and the local candidate queue.
  4. Show that Like and Follow are not executed automatically. User confirmation is recorded separately.

Limited-access behavior: If the app is not granted the relevant public-search access level, search may be restricted to the authenticated account's own content. The app reports a limited state and uses a low-call waiting mode rather than pretending that external public discovery succeeded.

3. threads_profile_discovery — exact public profile lookup

Why requested: The user reviews an explicitly specified public Threads account and its recent public posts to understand account relevance before deciding whether to engage manually.

  1. Open Direct Account Registration and enter an exact public Threads username.
  2. Run Profile Lookup and display the returned public profile.
  3. Retrieve and review public profile posts where the granted API access permits them.
  4. Show that the relationship queue is a local organizational record, not a bulk-follow mechanism.

4. Safeguards and user control

  • SAFE MODE is the default; scheduled collection does not perform Like, Follow, Repost or Reply.
  • Overlapping manual and scheduled collection runs are prevented from running simultaneously.
  • When public search access is limited, scheduled discovery uses a low-call waiting state.
  • Any API reply requires an explicit user action and remains subject to duplicate/cooldown/daily-limit safeguards.
  • The workflow does not access private Threads profiles, scrape follower lists, or bypass platform access controls.
  • Tokens and app secrets must not appear in reports, videos, screenshots or this website.

5. Before submitting through Meta App Dashboard

  1. Confirm that the requested permission names and real enabled capabilities match the actual app build.
  2. Provide a complete OAuth and in-app feature demonstration for each requested permission.
  3. Describe any restricted-access behavior accurately rather than showing simulated or invented search results as real API output.
  4. Provide the reviewer's supported access path and necessary testing instructions, if requested by Meta.
  5. Submit from Meta App Dashboard and check its decision there. Publication of this website does not submit an App Review request.
